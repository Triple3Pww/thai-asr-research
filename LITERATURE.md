# LITERATURE — the claim ledger

**What this file is:** every external claim that could change this repo, in one place, each with a
status saying whether *this box* has tested it. It is the reading side of `HISTORY.md`.

**What it is not:** a survey. Nobody here needs a paragraph summarising a paper. What the repo
needs is: *does this claim survive contact with our hardware, our Thai, and our latency budget?*

**The one rule — this repo has been burned twice:** a research sweep once confidently inverted our
own ear-verified findings, and a model card said "real-time" over a full-context checkpoint. So:

> 🔴 **A claim is not a finding.** Nothing in this file gets acted on because it is written here.
> A row leaves `UNTESTED` only when a measurement on this box moves it — and the measurement is
> named in the row.

---

## 0. How to use it

**Status vocabulary.** Five values, no others:

| status | meaning |
|---|---|
| `UNTESTED` | read, plausible, nobody has run it here. **The default. Most rows stay here.** |
| `CONFIRMED` | measured on this box and it held. Row names the run. |
| `REJECTED` | measured on this box and it did not hold. **Never delete these** — they are the most valuable rows. |
| `BLOCKED` | testing it needs something we don't have (data, a fine-tune, a licence). Row names the blocker. |
| `RULED-OUT` | fine work, but a locked decision excludes it (e.g. cloud hop inside the loop, spec §2 D2). Not a quality judgement. |

**Adding a row when you read something.** Minimum viable entry — do not write more than this:

```
| ID | the claim in ONE sentence, with its number | source | status | what would settle it here |
```

The claim column must contain **the number they claim**, not "it's fast". A claim without a number
cannot be tested and should not be a row.

**When a row gets tested,** change the status, add the measurement below the table as a short
`RESULT:` block (date + the run that produced it), and add an `HISTORY.md` entry. Leave the
original claim text exactly as written.

## 1. What this repo knows that the literature does not

Fill this in as you read — it is the point of the exercise. Current candidates, all measured here:

- ~~**Nobody publishes voice-to-voice latency from hand-marked true end-of-speech.**~~
  **HALF-STRUCK 2026-08-25 — this was too strong.** The Openbenchmarks TTFAB suite times
  caller-stops-speaking → agent audio starts, off the saved call recording: **the same origin as
  our clock** (row S7). So an origin-comparable external number does exist, and we are not alone.
  What survives, and is still worth publishing: (a) vendor *budgets* for those same products claim
  250–600 ms against 1558–1740 ms measured, a 2.5–3× gap nobody reconciles; (b) no such number
  exists for any **self-hosted Thai** stack; (c) the benchmark's own methodology page concedes no
  study measures across every latency layer.
- **The best Thai ASR is packaged as streaming and is not** (`att_context_size [-1,-1]`, measured
  2026-08-17). Not stated anywhere but the config file.
- **Zero-shot audio turn-detection fails on Thai and fails *confidently*** — Smart Turn v3.2 was
  wrong at 0.873–0.979 probability on speakers who kept talking for another 1.6–2.2 s.
- **A hybrid-SSM checkpoint's serving ceiling is Mamba cache blocks, not KV** (167 blocks; vLLM's
  default `max_num_seqs 256` refuses to start).
- **Q4 is dequantisation-compute bound, not bandwidth bound** — 1.56× fewer bytes buys 1.26×
  decode; effective bandwidth 258 GiB/s vs Q8_0's 318 against a ~417 GiB/s peak.
- ⭐ **Thai mid-turn and turn-final pauses are barely separable by duration: 41.9% EER.**
  Measured here 2026-08-27 on LOTUSDIS (8 sessions, ~2.0 h, Silero VAD pauses labelled by the
  TextGrid floor): same-speaker-resumes p50 **288 ms** vs floor-changes-hands p50 **416 ms**,
  n=1,137/396. Best duration-only threshold is 325 ms at 41.9% EER. Published acoustic-feature
  work reaches **20% EER** (E26), so roughly half the error is recoverable from signal that a
  pause-length timer discards. **The first pause-distribution numbers for Thai conversation in
  this repo** — and they say the 600 ms window mis-fires on **10.9%** of mid-turn pauses.
- **Consumer GPU boxes drift 25–45% across an evening and not equally between engines** — which
  invalidates most cross-session benchmark tables, ours included, unless bracketed in one window.

Each of these is either a paper this field is missing or a reason to distrust one. **When you read
a paper that already covers one, strike it from this list** — that is the honest outcome and it is
what the reading is for.

labelling rule was rebuilt (`loop/bench/eot_label.py`) and this row must be re-scored against
it before any verdict is drawn.

⚠️ **The gate this was measured against was inadequate, and that is the more useful finding.**
Spec §6 gated on EER and latency with **no ceiling on cut-off rate**, and compared a binary
rule's single operating point against a swept threshold's EER. It would have adopted a 58%
false-alarm endpointer against today's 15.9%. Any future gate needs a cut-off ceiling.

alarm 6.0%, independently reproducing the 23.3% particle ceiling from 4,688 floor changes. A
pause-duration timer sits at **39.9% EER**, reproducing the 41.9% from the 8-session probe.

measured as unusable.

of segments (durations run p10 1380 / p50 3180 / p90 6420 ms, so they are natural), and gambling
keywords hit only **0.7% / 1.7%** of segments. **The corpus is fine; it is the wrong shape.**

✅ **What YODAS is still good for:** a large, free, real Thai ASR corpus with human captions —
useful if a *sentence-completeness* classifier is ever wanted (the boundaries do beat the
mid-turn baseline). It cannot supply turn-taking labels.
